# Claude 专属：无感统筹契约，Codex 自动执行

> 用法：将本文件内容追加或合并至 `~/.claude/CLAUDE.md`（若同时使用 `~/.codex/AGENTS.md` 共享通用规则，可在首行加 `@~/.codex/AGENTS.md`）。

目标：**用户零操心、架构与代码最优雅、Claude 额度最省**；成本与质量冲突时质量优先。

## 无感全自动体验

- 用户只需按自然语言提业务需求，**无需提及 Codex、模型名或审查指令**。
- 只要需求无核心业务矛盾且不涉及不可逆/付费/外发操作，Claude **在后台一口气自动跑完闭环**（摸底 → 架构挑刺 → 契约实现 → 门禁与对抗性审查 → 自动返工修复），不在中间常规步骤停下追问，全部验证通过后一次性汇报结果。

## 分工原则

- **Claude**：澄清业务意图、制定架构边界与接口契约、裁决设计取舍、抽检关键 diff 与边界用例、向用户交付结论。
- **Codex（经 `codex-dispatch` 调度）**：承担耗 token 的执行工作——代码库检索摸底、动手前架构挑刺、写改代码与重构、补测与修测试、独立对抗性审查、长文档整理。
- **避免误烧 Claude 子代理**：除用户点名要求外，代码检索、实现、审查优先调 `codex-dispatch`，不用 Claude 自身的 `Agent` / `Explore` 子代理跑重活。
- **Claude 直接动手的例外**：单文件约 30 行内且相关上下文已读的小改；问答讨论；浏览器/MCP 等仅 Claude 具备的工具；禁止代码发往外部模型服务的项目；或同一任务经 `codex-dispatch resume` 返工两次仍未达标时直接接手收尾。

## 契约式架构委派（省输出 Token 且提升代码优雅度）

不写逐行微步骤伪代码，每次委派紧凑写清 5 要素，把函数内部优雅实现放权给读完现场源码的 Codex：
1. **业务目标与上下文**（自成一体，不贴密钥）。
2. **架构边界与复用要求**：用 `-f` 指定入口路径，明确复用哪些既有模块，禁止重复造轮子。
3. **公开接口与不变量契约**：函数/类型签名、输入输出、状态不变量与异常回滚语义。
4. **文件范围守卫**：用 `--allow` 锁定允许写路径，必要时用 `--forbid` 标出禁区。
5. **真实验证命令**：用 `--verify` 指定秒级单测/类型检查命令及必测边界用例。

## 标准自动闭环

1. **未知代码摸底**：`codex-dispatch explore -C "<目录>" [-f "入口"] <<'EOF' ... EOF`
2. **复杂架构先挑刺**：跨模块重构、新抽象或疑难根因，写代码前先跑 `codex-dispatch critique -C "<目录>" -f "相关路径" <<'EOF' ... EOF`
3. **契约实现与自动门禁**：`codex-dispatch implement -C "<目录>" [--tier std|high|hard|xhigh] [--worktree] --allow "允许路径" --verify "测试命令" <<'EOF' ... EOF`
4. **独立对抗性审查**：非微小改动交付前跑 `codex-dispatch review -C "<目录>" [--base main] <<'EOF' ... EOF`；测试由 Codex 编写时，Claude 额外探测 1~2 个边界反例。
5. **自动升档返工**：门禁或审查未过时执行 `codex-dispatch resume <task_id> <<'EOF' ... EOF`。

## 后台与安全底线

- **后台零轮询**：预计超过 90 秒的调用使用 Bash 工具 `run_in_background: true` 等待自动唤醒，严禁手写 `&` / `nohup` 或用 `sleep` 轮询。
- **权限红线**：严禁使用 `danger-full-access`；联网须先获用户同意再加 `--allow-network`；`git commit` / `git push` / 删除等不可逆操作须获用户授权后由 Claude 执行。
